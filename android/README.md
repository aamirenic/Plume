# PLUME for Android

PLUME's Android shell is a Kotlin/Jetpack Compose front end over the same Rust
curve engine as the desktop studio.  It is not a reimplementation: document
editing, projection, stroke capture, mesh generation, undo history, autosave,
and every exporter run in `plume-core` through a UniFFI bridge loaded with JNA.

```
Compose UI  ──  PlumeViewModel  ──  uniffi.plume_ffi (Kotlin)  ──  JNA
                                                              │
                                                     libplume_ffi.so
                                                              │
                                                         plume-core
```

The Android app starts from an autosaved sketch when one exists, otherwise from
the **Ribbon Bloom** gallery scene.  The running document is autosaved to
`files/autosave.plume.json` and flushed synchronously when the app leaves the
foreground.

## What is included

- One-finger pressure-aware drawing; two-finger orbit and pinch; three-finger
  pan; tap-to-erase.
- All built-in brushes, sorted by category, with procedural swatches.
- Camera-aware software previews, so orbiting and zooming work without a wgpu
  context on mobile.
- Gallery browser generated by the Rust scene engine.
- Camera shot / keyframe scrubbing with an automatic return to the authoring
  camera.
- Undo and redo with gesture-level history.
- System file picker (SAF) export to `.plume`, `.feather`, GLB, glTF, OBJ, STL,
  USDZ, and PNG.
- ARCore tabletop placement: camera feed, point cloud, hit-test anchors, packed
  scene meshes drawn with OpenGL ES 2.0, pinch resize, and double-tap rotation.
  No Sceneform or third-party AR renderer is used.
- Camera permission is requested only when entering AR.  The app has no
  network permission and performs no analytics or uploads.

## Requirements

| Tool | Version |
| --- | --- |
| JDK | 17 or newer |
| Android SDK | Platform 35, Build Tools 35.0.0 |
| Android Gradle Plugin | 8.7.3 |
| Kotlin | 2.0.21 |
| Rust | stable, with Android targets |
| cargo-ndk | current release |
| ARCore | optional; installed on the test device for placement |

The generated Kotlin bindings are committed under
`app/src/main/java/uniffi/plume_ffi/`, so a Gradle-only build does not need a
host Rust build.  The native libraries do need to be built once for each ABI.

## 1. Build the native bridge

From the repository root:

```bash
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk

export ANDROID_NDK_HOME="$ANDROID_SDK_ROOT/ndk/27.2.12479018"
cargo ndk \
  -t arm64-v8a \
  -t x86_64 \
  -o android/app/src/main/jniLibs \
  build --release -p plume-ffi
```

This produces:

```text
android/app/src/main/jniLibs/
├── arm64-v8a/libplume_ffi.so
└── x86_64/libplume_ffi.so
```

Add `armeabi-v7a` or `x86` to `abiFilters` and the cargo-ndk command only if you
need those older ABIs; the default distribution targets 64-bit devices and the
emulator.

## 2. Regenerate the Kotlin bindings (optional)

Checked-in bindings match the current Rust API.  Regenerate after changing
exported UniFFI types or methods:

```bash
cargo build -p plume-ffi
cargo run -p plume-ffi --bin uniffi-bindgen -- generate \
  --library target/debug/plume_ffi.dll \
  --language kotlin \
  --out-dir android/app/src/main/java \
  --no-format
```

Use `libplume_ffi.so` on Linux or `libplume_ffi.dylib` on macOS for the
`--library` path.  The metadata is identical across host platforms.

## 3. Build and run

Open the `android/` directory in Android Studio, or use the checked-in wrapper:

```bash
cd android
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```

`android/local.properties` is intentionally not committed.  Android Studio
writes it automatically; otherwise set:

```properties
sdk.dir=/path/to/android-sdk
```

The Gradle project uses `namespace = "dev.plume.app"`, `minSdk = 26`, and
`targetSdk = 35`.  The launcher mark and every in-app icon are procedural vector
or Compose drawings; no Feather artwork, fonts, icons, binaries, or assets are
used.

## ARCore placement

1. Draw or open a scene with at least one visible curve.
2. Tap **AR** in the viewport or **Place with AR** in the menu.
3. Grant camera access.  If prompted, install **Google Play Services for AR**.
4. Move the phone until ARCore finds a horizontal or vertical plane.
5. Tap a surface to place the sketch.  The combined scene is fitted to roughly
   30 cm and sits on the tapped surface.
6. Pinch to resize, double-tap to turn 45°, and tap elsewhere to reposition.

AR requires a supported device and the ARCore service.  The manifest marks AR
as optional, so the editor installs and runs on devices without it.  Placement
loads the current autosave through a separate `PlumeSession`, requests
`sceneMeshes("draft")` from Rust (little-endian `f32` positions/normals and
`u32` triangles), converts to unindexed ES 2.0 buffers, and draws the camera
background with `GL_TEXTURE_EXTERNAL_OES`.

## Verification

Without a connected device, compile and lint locally:

```bash
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

With a device or emulator:

```bash
./gradlew :app:installDebug
adb shell am start -n dev.plume.app/.MainActivity
```

The Rust side is tested from the repository root with
`cargo test --workspace`, including FFI tests for packed AR meshes, previews,
eraser picking, animation camera restoration, undo, and export.

## Notes and limits

- Mobile rendering is intentionally a fast software preview of the same scene,
  not a wgpu viewport.  Final surfaces, lights, post-processing, GIF/MP4 capture,
  and print-grade renders are produced by the desktop studio.
- Import of existing OBJ/glTF/STL/`.plume` files is handled by the desktop
  studio.  Android restores its own autosave and starts from the built-in
  gallery.  SAF export is fully supported on mobile.
- ARCore plane visualisation is shown through the detected point cloud; the app
  does not draw ARCore planes.
- The native bridge is loaded by JNA.  Keep the JNA AAR dependency and
  `libplume_ffi.so` ABI folders in sync; a missing ABI fails at first FFI call.
