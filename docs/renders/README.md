PLUME's own scenes and UI; no third-party screenshots or artwork are included.

| `android-gallery.png` | Android scene gallery |

| `ribbon-bloom.png` … `clean-stage.png` | Headless 1200×750 renders of all eight gallery scenes |

The eight scene renders were produced with the software wgpu adapter on a
Windows host because the local Intel UHD 620 driver crashes during hardware
device creation. The rendering path, shaders and post stack are the same; only
the adapter differs.

## Regenerating scene renders

From the repository root, with the sandbox pointed at the repository:

```powershell
$env:PLUME_SANDBOX = (Get-Location).Path
cargo build -p plume-app
foreach ($id in @('ribbon-bloom','wire-flora','paper-lanterns','neon-knot',
                  'terrazzo-tile','ink-orbit','calligraphy-cloud','clean-stage')) {
    target\debug\plume.exe --gallery $id --render "docs\renders\$id.png" `
        --width 1200 --height 750 --quality high
}
```

On Unix:

```bash
export PLUME_SANDBOX="$PWD"
cargo build -p plume-app
for id in ribbon-bloom wire-flora paper-lanterns neon-knot \
          terrazzo-tile ink-orbit calligraphy-cloud clean-stage; do
  target/debug/plume --gallery "$id" --render "docs/renders/$id.png" \
    --width 1200 --height 750 --quality high
done
```

`desktop-floating.png`, `desktop-brushes.png`, `desktop-inspector.png`,
`desktop-studio.png`, `scene-gallery.png`, `import-units.png` and
`unsaved-changes.png` are 1200×600 window captures from the software-adapter
playtest. They are not generated by headless mode. The four `android-*.png`
files are 1080×2400 emulator captures of the debug-signed Android preview.

## Visual checks performed

- No black frames or missing post-processing output
- Gallery scene content is visible and framed by the document camera
- Guide wireframes and grid are present without obscuring the art
- Emissive Neon Knot survives tone mapping
- Terrazzo band colours match the gallery preview
- Clean Stage is intentionally empty apart from grid, axes and origin gizmo
